# ReadYou fork —— 手写的 baseline profile（不是真机采集）
#
# 背景：AndroidX 依赖（Compose runtime 等）AAR 里自带的 baseline-prof.txt 已经由 AGP
# 自动合并，但**应用自身**启动与首屏路径的 profile 一直是空的。真机采集需要
# macrobenchmark 模块 + 一台设备/模拟器（CI 上还得是有 KVM 的 Linux runner），成本高。
#
# 这里退一步：手写一份只覆盖「启动入口 + 首屏必经类」的最小 profile。
# 收益小于真机 profile，但它零设备依赖，并且能验证整条链路是通的
# —— 构建后 assets/dexopt/baseline.prof 应该比原来的 7,224 字节大。
#
# 注意：下面用的是**类级规则**，意思是该类所有方法都会参与 AOT 编译。
# 不要往里堆无关的类，那只会增大 odex 体积、延长安装时的 dex2oat 时间。
